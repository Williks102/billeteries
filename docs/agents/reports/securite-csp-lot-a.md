# Audit sécurité : CSP lot A (claude/csp-lot-a)

Verdict : OK avec réserves. Aucun critique ni élevé. Tests Security + RenderDeployment + SecurityHeadersImages : 65 verts (exécutés).

## Moyen
- M1. Corps `application/reports+json` entièrement parsé AVANT le plafond 16 Ko. `TrimStrings`/`ConvertEmptyStringsToNull` (global) appellent `$request->json()` si `isJson()` (« +json » correspond), vendor/laravel/framework/src/Illuminate/Foundation/Http/Middleware/TransformsRequest.php:32-34. Apache sans `LimitRequestBody` (docker/apache-render.conf), `post_max_size` ne vaut que pour les formulaires ; `ValidatePostSize` ne regarde que Content-Length (absent en chunked). Le contrôle de app/Services/CspReportRecorder.php:34-47 arrive trop tard. Scénario : POST de plusieurs Mo en `reports+json` -> json_decode complet (profondeur 512), mémoire/CPU, éventuel 500 (fatal memory_limit). Impact limité par 30/min/IP mais IP falsifiable (voir F2). Correctif (agent backend) : ne plus accepter `reports+json` (la politique n'utilise que `report-uri`, donc le navigateur envoie `application/csp-report`) ; ou `withoutMiddleware([TrimStrings::class, ConvertEmptyStringsToNull::class])` sur la route (routes/web.php:58-69) ; ou `LimitRequestBody 16384` pour ce chemin côté Apache.

## Faible
- F1. Pollution des 500 lignes : `directive` n'est pas en liste blanche (`[a-z-]{1,40}`, CspReportRecorder.php:~118) et `blocked` accepte n'importe quel hôte. Un attaquant remplit 500 lignes en ~5 min (120 écritures/min) et les vraies violations nouvelles sont ignorées ; hits gonflables. Pas de fuite, pas d'impact sur le site. Correctif : liste blanche des directives CSP connues (script-src, script-src-elem, script-src-attr, style-src*, img-src, font-src, connect-src, frame-src, default-src…) sinon rejet ; ajouter dans l'écran un bouton/commande de purge ; envisager de purger les lignes à 1 hit de plus de 30 jours.
- F2. Limite par IP contournable si `TRUSTED_PROXIES="*"` (render.yaml:47) : Symfony prend l'entrée X-Forwarded-For la plus à gauche, contrôlée par le client -> la clé throttle change à chaque requête (et crée une ligne de cache `database` par IP inventée). Le plafond global 120/min (CspReportRecorder.php:~170) protège la base, mais un attaquant peut l'épuiser et priver les vrais rapports (déni de télémétrie seulement). Défaut préexistant, vaut pour tous les throttles (login). Correctif : régler TRUSTED_PROXIES sur les IP/plages de Render ; documenter.
- F3. Le plafond de 500 lignes (count puis insertOrIgnore) est sans verrou : dépassement de quelques lignes seulement, bénin (documenté).
- F4. Garde-fou statique (CspReportOnlyTest.php:148) : `[^>]*` s'arrête au premier `>` d'un attribut, et `\bsrc\s*=` accepte `data-src=`. Théorique, aucun cas actuel.
- F5. Réponse 429 distincte du 204 (documenté ; signal de limitation seulement, acceptable).
