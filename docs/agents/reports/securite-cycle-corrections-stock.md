## Nouveaux constats
- S-6 Élevé (disponibilité) : generateQrCodes (CheckoutService.php:472-488) s'exécute DANS la requête de checkout après commit. Par billet : 3 essais Google Charts (Http 8 s + file_get_contents 5 s en repli), puis QR Server (5 s), puis 3 s : jusqu'à ~60 s par billet x 10 billets (quota) = worker PHP bloqué des minutes. Google Charts est arrêté depuis 2019 : en production CHAQUE billet passera probablement par tous les replis. Un attaquant (10 checkouts/min/IP, plusieurs IP) épuise php-fpm sans rien exploiter. Correctif : générer en local (simplesoftwareio/simple-qrcode et bacon déjà installés, SVG/PNG sans réseau) ; sinon job en file (dispatchAfterResponse/queue) avec timeout 3 s, sans repli file_get_contents. Agent : paiements-stock.
- S-7 Moyen (confidentialité) : QRCodeService envoie à chart.googleapis.com et api.qrserver.com l'URL url('/verify-ticket/{ticket_code}') (QRCodeService.php ~l.55-65, 165-185). Le code du billet est le secret porteur ; /verify-ticket et /api/verify-ticket sont publics, sans throttle, et renvoient les infos du billet (relation order.user chargée). Un tiers (ou ses logs) obtient des codes de billets valides. Correctif : QR local (même que S-6) ; supprimer les replis réseau ; ajouter throttle sur les routes verify. Agent : paiements-stock + backend.
- S-8 Moyen (outillage) : MySqlTestGuard ignore DB_URL (surcharge host/base de la connexion) : migrate:fresh peut viser une vraie base avec un nom en `_test` factice dans TEST_MYSQL_DATABASE. Correctif : refuser si getenv('DB_URL') est défini, ou construire la connexion sans url (config(['database.connections.mysql.url'=>null])) et relire host/base depuis config après surcharge ; regex `/^[a-z0-9_]*_test\z/D`. Agent : paiements-stock.
- S-9 Moyen : XSS stocké préexistant : events/show.blade.php (showAlert) injecte `${message}` en HTML brut ; les messages CartController (l.64, 73) incluent ticketType->name (saisi par l'organisateur). Correctif : textContent/escape côté JS (ou e() du nom). Agent : frontend.
- S-10 Faible : logs de billets : Log::info/warning avec ticket_code et $e->getMessage() (messages Guzzle contenant l'URL du QR, donc le code) volume accru par la génération systématique. Correctif : ne pas journaliser le code complet ni le message brut.
- S-1 (reste) Élevé en production : pas de vérification d'email/captcha ; IPv6 /56. Agent : paiements-stock + propriétaire (Turnstile).
